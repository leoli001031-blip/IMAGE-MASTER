# Image Master 完整使用说明

这份说明面向内部试用、演示和日常自测。当前版本适合内部 Demo 和真实链路验证，还不建议直接公开给外部用户使用。

## 1. 产品一句话

Image Master 是一个本地优先的商业图片 Agent 工作台。

你把商品、模特、场景、风格、文案等素材放进项目里，再用自然语言告诉 Agent 要做什么。Agent 会规划图片类型、数量、比例、参考图使用方式、文案是否进图，然后把生成结果铺到无限画布上。

核心心智是：

```text
项目 -> 素材资产 -> Agent 规划 -> 生成任务 -> 结果墙 -> 查看详情/重做/保存资产/打开文件夹
```

## 2. 适合做什么

适合：

- 淘宝详情页图组
- 小红书封面和内容图
- 商品主图、白底图、细节图
- 商品海报和卖点图
- 模特展示图
- 多场景生活方式图
- Amazon 或跨平台上市图组
- 商品多角度白底参考图
- 内部视觉方向探索和 Demo 样例生产

不适合直接承诺：

- 商品细节像素级还原
- 所有平台规则自动合规
- 每次 provider 都稳定成功
- 所有模卡都能 100% 锁定同一个人
- 不上传真实商品图也能锁定真实商品身份

## 3. 启动方式

### 开发版

```bash
npm install
cp env.example .env
npm run dev
```

打开：

```text
http://localhost:3000/canvas
```

常用页面：

- `/canvas`：主工作台
- `/projects`：项目入口和模板入口
- `/settings`：API 配置
- `/models`：模特资产实验入口
- `/result`：旧结果页，当前主流程优先看 `/canvas`

### Electron 本地版

```bash
npm run build:standalone
npm run electron:prepare-server
npm run electron
```

如果要打私有本地包：

```bash
npm run electron:build:dir
npm run electron:build:dmg
```

注意：带 `.env` 的 Electron 包只适合自己本机测试，不要公开分发。

## 4. API 配置

可以通过 `.env` 或 `/settings` 配置。

常用变量：

```text
OPENAI_API_KEY=
OPENAI_BASE_URL=
TEXT_MODEL=
TEXT_API_KEY=
TEXT_BASE_URL=
IMAGE_MODEL=
IMAGE_API_KEY=
IMAGE_BASE_URL=
VISION_MODEL=
VISION_API_KEY=
VISION_BASE_URL=
```

建议分工：

- `TEXT_*`：用于 Agent 规划和 prompt writer
- `IMAGE_*`：用于真实生图
- `VISION_*`：用于视觉分析和资产理解

真实生图会消耗 provider 额度。只想测试规划时，优先跑 plan-only 脚本，不要启动真实 image jobs。

## 5. 基本概念

### 项目

项目是一组商业图片任务的容器。比如：

- 一个投影仪上市项目
- 一个包包淘宝详情页项目
- 一组服装模特展示项目

建议一个真实商品或一次营销目标建一个项目。

### 素材资产

素材资产是 Agent 可以使用的输入。常见类型：

| 类型 | 用途 | 注意 |
| --- | --- | --- |
| 商品 | 锁定商品形状、材质、颜色、五金、logo、结构 | 真实商品身份必须上传真实图片 |
| 模特 | 提供人物身份、气质、身形或模卡 | 可能出现神态锁定，需要下游自然身份参考 |
| 场景 | 提供空间、光线、氛围、机位方向 | 可用文字或图片辅助 |
| 风格 | 提供拍摄质感、色调、后期方向 | 不应该覆盖商品身份 |
| 文案 | 卖点、标题、画面文字、导出文案 | 默认结构化，按任务判断是否烧进图 |
| 知识 | 平台规则、拍摄 SOP、行业经验 | 给 Agent 判断，不直接暴露原文 |

### Agent

Agent 是主控入口。你用自然语言说需求，它负责规划：

- 要生成哪些图
- 每张图的用途
- 每张图的比例
- 哪些参考图必须锁定
- 哪些参考图只是风格或氛围
- 文案是否进入图片
- 是否需要多场景、多商品、多模特矩阵

### 结果墙

生成后的图片会出现在无限画布上，按真实宽高比展示。点击图片可以查看：

- 大图
- prompt
- 使用的参考图
- provider 和 model 信息
- diagnostics
- 失败原因
- 重做、下载、打开文件夹、保存为资产

## 6. 从 0 到 1 的标准流程

### 第一步：新建或打开项目

进入 `/projects` 或 `/canvas`。

如果是新项目，建议先明确项目目标：

```text
我要给一个便携投影仪做一套淘宝详情页和小红书推广图。
需要白底主图、卖点海报、生活方式场景图、模特使用图。
其中卖点海报和详情页图需要把短文案放进画面。
```

### 第二步：准备素材

最低限度建议：

- 商品真实参考图：必须有
- 文案/卖点：如果要做海报或详情页，建议有
- 场景或风格：可以有，没有也能让 Agent 生成方向
- 模特：需要人物图时再加

商品真实身份的规则很重要：

```text
真实商品图 = 可以锁商品
纯文字商品描述 = 只能做概念 mockup
AI 临时生成的概念商品 = 不应假装是真实商品锁定
```

### 第三步：让 Agent 规划

在右上角 Agent 输入框描述需求。

好的描述方式：

```text
用这个商品做一套淘宝详情页，目标是年轻租房用户。
需要 12 张图：白底主图、细节图、卖点海报、客厅场景、卧室场景、模特使用图、小红书封面。
卖点包括轻便、清晰、夜晚观影、易收纳。
海报和详情页需要短文案进图，其他场景图不要文字。
```

如果有多个商品或多个场景，要直接说清楚：

```text
这 3 件衣服分别生成独立图组，使用同一个模特。
每件衣服要白底图、模特正面、侧身、行走、坐姿、街拍场景各 1 张。
不要把三件衣服混成一件商品。
```

### 第四步：检查 Agent 计划

生成前先看计划是否合理。重点检查：

- 图片数量是否对
- 比例是否符合用途
- 商品图是否使用真实商品参考
- 模特图是否使用模特参考
- 场景/风格是否只是辅助，不覆盖商品
- 文案图是否明确 burn-in
- 非文案图是否保持无字
- 多商品/多场景是否被拆成矩阵，而不是混成一张

如果计划不对，不要直接生成。用一句话改：

```text
把商品图和模特图拆开，每个商品独立生成，不要混在一个商品资产里。
```

或：

```text
只有海报和详情页烧字，生活方式图不要文字。
```

### 第五步：开始生成

确认计划后再启动生成。

建议：

- 小项目可以一次跑
- 大项目先跑几张确认 provider 状态
- 多图大项目避免短时间手动狂点所有任务
- 失败单张优先重试，不要立刻改系统逻辑

### 第六步：审核结果

图片出来后逐张检查：

- 商品形状和关键细节是否准确
- 文案有没有写到安全区
- 文案有没有改到商品标签、瓶身、屏幕、logo 或包装上
- 模特身份是否还能接受
- 光影和场景是否统一
- 手部、接触关系、透视是否明显穿帮
- 平台用途和比例是否合适

### 第七步：保存和复用

满意的输出可以保存成资产：

- 好的商品白底多角度图 -> 商品资产
- 好的模特自然参考图 -> 模特资产
- 好的场景图 -> 场景资产
- 好的摄影质感 -> 风格资产

后续项目可以直接复用这些资产。

## 7. 修改和二次生成

修改分四种情况，不要混在一起处理。

### 7.1 生成前改计划

如果 Agent 计划还没开始生图，直接用自然语言改计划。

适合：

- 图片数量不对
- 比例不对
- 有些图不该烧字
- 多商品没有拆开
- 场景或用途理解错了

示例：

```text
把这套计划改成 16 张，增加 3 张模特使用图和 2 张细节图。
只有海报和详情页烧字，白底图、场景图、模特图都不要文字。
```

或：

```text
这 5 件衣服要分别出图，不要合成一件商品。每件衣服都用同一个模特生成 4 张。
```

### 7.2 单张图出来后修改

如果某一张图基本可用，只是局部不满意，点击那张图进入详情，再用“重做/修改”给一段短指令。

单张修改应该默认带回原始参考图和原始 prompt，不需要用户重新上传素材。

适合：

- 文案位置不对
- 模特动作太僵
- 商品比例稍微不对
- 背景太乱
- 光影不协调
- 想换一个构图或机位

好的修改指令要短、具体：

```text
保留商品和整体构图，只把文案移到左上角背景留白区域，不要写到商品上。
```

```text
保留同一个模特和同一个包，动作改自然一点：身体侧向 30 度，头轻微右偏，眼睛看镜头旁边，左手扶包带。
```

```text
保留商品外观不变，背景改得更干净，减少桌面杂物。
```

不建议这样写：

```text
优化一下。
```

这类指令太宽，模型会不知道该保留什么、该改什么。

### 7.3 整组结果统一修改

如果一整组图方向都对，但整体风格、文案策略或图组结构要调整，回到 Agent 输入框，按“整组修改”说。

适合：

- 整体太像电商合成图，想更真实
- 所有模特动作太重复
- 整组都需要更高级、更克制
- 所有烧字图要统一字体区域
- 需要补一组新比例

示例：

```text
基于刚才这组结果，保留商品和图组结构，整体改得更像真实街拍/真实室内摄影。减少电商合成感，光影更自然。
```

```text
这组图里的模特动作太重复。重新生成模特展示图，每张指定不同动作和眼神，不要复用同一个站姿。
```

```text
保留现有 12 张图，再额外补 4 张 4:5 竖版海报，文案放在背景安全区。
```

### 7.4 源资产不对时先改资产

如果问题来自源资产，不要一直改单张结果。先把资产修好。

典型情况：

- 商品多角度参考图不像原商品
- 模卡导致表情太死
- 场景参考太杂乱
- 风格参考太影棚或太廉价
- 文案资产里卖点/禁用词不清楚

处理方式：

- 商品不准：重新上传真实商品多角度图，先生成更准确的白底多角度商品资产。
- 模特太死：重新做更自然的下游身份参考，减少棚拍模卡气质。
- 场景不对：先生成或上传更明确的场景资产。
- 文案不对：把画面文字、卖点参数、禁止声明、导出文案分开写。

资产修好后，再让 Agent 基于新资产重跑图组。

### 7.5 文案修改

文案没烧进图时，改文案只是改结构化信息，成本低。

文案已经烧进图时，修改文案需要重做图片或局部重做。此时要明确：

```text
只修改画面文字，其他商品、人物、背景和构图尽量保持不变。
```

同时继续要求：

```text
文字放在背景安全区，不要写到商品本体、标签、屏幕、瓶身、logo 或包装上。
```

## 8. 常见工作流

### 商品白底多角度图

输入：

- 多张同一商品照片，最好包含正面、侧面、背面、细节

需求示例：

```text
把这些商品参考图整理成一张白底多角度商品参考图。
只保留商品身份，不要模特、场景、文案和装饰。
```

用途：

- 作为后续海报、场景图、模特图的商品锁定参考

### 淘宝详情页图组

输入：

- 商品参考图
- 卖点文案
- 可选模特、场景、风格

需求示例：

```text
做一套淘宝详情页图组，8 到 12 张。
包含白底主图、卖点海报、细节特写、场景使用图、收尾图。
卖点图和详情页图需要短文案进图，其他图保持无字。
```

### 小红书封面

输入：

- 商品图
- 风格方向
- 标题或短文案

需求示例：

```text
做 4 张小红书封面候选。
画面要有真实生活感，标题短一点，文字放在干净留白区域。
不要把字写到商品本体上。
```

### 模特多场景展示

输入：

- 模特参考
- 商品或服装参考
- 多个场景方向

需求示例：

```text
用同一个模特做 3 个场景：室内、街头、商场。
每个场景 3 张，姿势和机位要有变化。
保持同一个人物身份，但不要复制模卡里的僵硬表情和棚拍姿势。
```

### 多商品 + 单模特

输入：

- 一个模特资产
- 多个商品或多件衣服

需求示例：

```text
用同一个模特分别展示这 5 件衣服。
每件衣服独立生成 4 张图：正面、侧身、行走、坐姿。
不要把多件衣服融合成一件。
```

## 9. 文案和烧字规则

文案分几类：

- 画面文字：可以出现在图片里
- 卖点参数：给 Agent 理解商品，不一定进图
- 禁止声明：不能写、不能夸大、不能承诺的内容
- 导出文案：用于标题、描述、备注，不默认进图

默认原则：

```text
文案先结构化。
只有用户明确需要海报、详情页、小红书封面、商品卖点图等，才考虑 burn-in。
```

烧字时必须遵守：

- 文案短
- 字要清楚
- 放在画面安全区
- 不压住商品关键细节
- 不写到商品标签、瓶身、屏幕、镜头、logo、包装、衣服吊牌上
- 不写长段落

好的说法：

```text
这 3 张卖点海报需要把短文案放进画面，文字放在背景留白区域。
```

不好的说法：

```text
把这些文案都写到商品上。
```

## 10. 参考图使用规则

### 商品参考

商品参考是强约束。它负责：

- 形状
- 比例
- 材质
- 颜色
- 五金
- logo 或真实标识位置
- 结构细节

没有真实商品图时，不应该承诺真实商品锁定。

### 模特参考

模特参考用于身份、气质、身形。

如果模卡导致神态太死，可以在需求里明确：

```text
保持同一个人物身份，但动作、表情、眼神和姿态重新设计。
像摄影师现场指导模特一样，给出具体动作：头往哪里偏、眼睛看哪里、手怎么放、重心在哪只脚。
不要复制模卡里的固定微笑和棚拍站姿。
```

### 场景参考

场景参考用于空间和光线。它负责：

- 室内/室外环境
- 光源方向
- 背景氛围
- 透视关系
- 阴影逻辑

### 风格参考

风格参考只负责质感：

- 色调
- 胶片感/街拍感/商业棚拍感
- 镜头感觉
- 后期质感

风格不应该覆盖商品身份。

## 11. 常见问题

### 生成失败

先看详情里的 diagnostics。

如果看到 provider socket、empty response、timeout 等问题，通常是上游 provider 或网络连接问题。先重试单张，不要马上改 prompt 或系统逻辑。

### 商品多角度图不像原商品

先确认输入是不是同一个真实商品的多张照片。然后减少生活方式、模特、文案等约束，让这一步只做商品身份整理。

### 文案没有进图

检查需求是否明确要求：

```text
需要把短文案烧进图片
```

如果只是给了卖点，Agent 可能会把它当作结构化信息，不默认进图。

### 文案写到了商品上

这是需要修的结果。重做时明确：

```text
文案只能放在背景留白或安全区，不能写到商品本体、标签、屏幕、瓶身、logo 或包装上。
```

### 模特表情太僵

减少“完全一致、严格复制”这类说法。改成：

```text
只保持身份，不复制表情和姿势。
动作要具体：身体侧向 30 度，头轻微右偏，眼睛看镜头旁边，左手扶包带，右脚承重。
```

### 大批量任务卡住

先不要重复点击。检查 job queue 和 diagnostics。大项目建议分批跑，或控制并发。

### 不想花 API 费用

只跑 plan-only：

```bash
npm run verify:agent-plan
npm run smoke:real-acceptance-projects
```

不要运行带 `:real` 或明确 real provider 的脚本。

## 13. 演示建议

稳定演示优先使用已有固定样例，避免现场 provider 波动影响观感。

演示顺序：

1. 打开项目。
2. 展示素材库。
3. 输入自然语言需求。
4. 展示 Agent 计划。
5. 展示结果墙。
6. 点击一张图看详情、prompt、参考图和 provider 信息。
7. 展示保存为资产和打开本地文件夹。

不要把 Demo 讲成“已经生产级上线”。更准确的表述是：

```text
内部 Demo 链路已经闭环，接下来要继续收队列稳定性、provider 失败体验、商品多角度准确性和模特身份参考。
```

## 14. 安全注意

- 不要提交 `.env`
- 不要提交 `.data/`
- 不要公开 provider key
- 不要把带私有 `.env` 的 Electron 包发给别人
- 不要把 settings API 暴露到公网
- 真实 provider 脚本运行前确认会花费额度

## 15. 推荐的日常使用习惯

- 一个商品一个项目
- 真实商品必须上传真实图
- 先让 Agent 出 plan，再决定是否生图
- 大图组先小批量试跑
- 文案是否进图要说清楚
- 失败先看 diagnostics，再决定重试或改需求
- 好结果及时保存为资产
- 定期用 `npm run generated:cleanup` 做 dry-run 清理
