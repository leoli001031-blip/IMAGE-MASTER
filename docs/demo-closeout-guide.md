# Image Master Demo 收尾指南

这份文档用于内部演示和交接。它不是公开发布说明，也不是生产上线承诺。

## 当前判断

Image Master 现在可以视为内部 Demo 基本收尾：核心链路已经能讲通，也有一套可复用的真实生成样例。它还不适合直接公开给外部用户试用，因为 provider 稳定性、商品身份锁定、队列体验和少数 UI 细节仍然需要继续打磨。

一句话定位：

用户在项目里准备素材，用一个 Agent 输入说清楚需求，Agent 规划图组、比例、参考图和文案策略，结果以无限画布图片墙呈现。

## 演示主线

推荐把演示讲成 5 步：

1. 打开项目画布。
2. 准备或上传资产：商品、模特、场景、风格、文案。
3. 在 Agent 输入框里说需求，例如“做一套淘宝详情页和小红书封面，部分图需要把短文案放进画面”。
4. Agent 输出计划：图片数量、用途、比例、参考图、文案是否进图。
5. 生成结果落到无限画布。点击任意图片查看大图、prompt、参考图、provider 信息，并可保存为资产或打开本地文件夹。

演示时强调这四句话就够：

- 现在的用户心智是“项目 + 素材 + Agent + 结果墙”。
- 用户不用填复杂表单，主要靠自然语言描述商业图需求。
- 商品真实身份必须有真实商品参考图。
- 文案是结构化的，只有明确需要时才烧进图，并且必须放在安全区，不能改商品本体。

## 三种演示模式

### 1. 稳定演示

使用已经生成好的固定样例，不再调用 provider。

适合给人看产品形态、结果墙、详情面板和“打开本地文件夹”。这是最稳的演示方式。

### 2. Plan-only 演示

只跑 Agent 规划，不真实生图。

适合展示自然语言如何拆成图片用途、比例、参考图角色、文案策略和批量任务。

推荐命令：

```bash
npm run verify:agent-plan
npm run smoke:agent-plan-20
npm run smoke:real-acceptance-projects
```

这些检查不应该调用真实 image provider。

### 3. 真实生成演示

只在 provider、key、网络状态都稳定时使用。

建议先做小批量，再做大批量。大批量不要一次手动猛点所有 job，避免 SQLite 短时间写入竞争。真实演示可以控制在 4 个左右并发，等第一批稳定落图后再继续。

## 启动

开发版：

```bash
npm install
cp env.example .env
npm run dev
```

打开：

```text
http://localhost:3000/canvas
```

Electron 本地版：

```bash
npm run build:standalone
npm run electron:prepare-server
npm run electron
```

如果需要把当前 `.env` 带入私有本地包，确认这是只给自己测试用，不要公开分发。

## 演示前检查

建议演示前按顺序做：

```bash
npx tsc --noEmit
npm run verify:trial
npm run verify:agent-plan
```

再确认：

- `.env` 里有正确的 text/image provider 配置。
- 不要把 `.env`、`.data/`、生成图片和私有日志提交到公开仓库。
- 固定样例输出目录存在。
- 如果真实生图，先跑 1 到 3 张确认 provider 正常。
- 如果要烧字，确认 copy policy 是 burn-in，且 prompt 要求文案进入画面安全区。

## 已知风险

Provider 失败：

真实测试里出现过 `PROVIDER_SOCKET_CLOSED`。这通常是上游 provider 或中转连接问题，不一定是本地软件逻辑错误。优先重试单张或切到固定样例演示。

概念商品被拦截：

如果商品是 AI 临时生成的概念图，系统可能不会把它当成真实商品身份锁定。真实商品身份必须上传真实 PNG/JPG 参考图。这是预期 guard，不是 bug。

大批量启动卡住：

如果短时间内强行启动很多 job，可能触发 SQLite 写入竞争。演示时不要用手动脚本同时启动过多任务。后续应把“受控启动队列”产品化。

模特一致性：

模特资产和多参考图仍然可能存在神态锁定、动作重复、脸部光影不融等问题。演示时不要承诺任何模卡都能 100% 锁身份。

## 不要这样宣传

不要说：

- 已经生产可上线。
- provider 已经完全稳定。
- 商品细节能像素级复刻。
- 所有平台规则、广告规范、法律合规都自动保证。
- 模特身份在所有场景下都能 100% 一致。

可以说：

- 内部 Demo 链路已经能闭环。
- Agent 能把自然语言需求拆成一组商业图计划。
- 结果可追溯到 prompt、参考图和 provider 信息。
- 商品真实身份有 guard，缺少真实参考图时不会假装能锁定。
- 文案进图可以按任务判断，并有安全区规则。

## 后续收尾项

Demo 后最值得继续做的是：

- 把受控队列启动做进产品，不再依赖手动控制大批量并发。
- 固化一个可导入的演示项目模板，包含固定样例和讲解路径。
- 继续打磨结果墙视觉密度，让不同宽高比的图更轻、更好浏览。
- 改善 provider 失败时的重试、诊断和用户提示。
- 继续优化真实商品多角度图，避免“多角度合集”偏离原商品身份。
- 继续优化模特资产的下游身份参考，减少神态锁定。
